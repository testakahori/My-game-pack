# 埋め立て研究室MAP

完成ワールドは、このフォルダーの `umetate_lab_map/` に保存しました。
コピー元は `.minecraft/saves/umetate_bridge01` です。元ワールドは変更していません。
表示名は `umetate_lab_map`、自然湧きはオフです。ネザー・エンドのデータもコピーしています。

ワールド本体は約55 MBです。プレイヤーデータを含むローカルのコピーなので、Gitの管理対象にはしていません。
別の環境へ持っていくときは、`umetate_lab_map/` フォルダーを丸ごとコピーしてください。
中の `umetate_lab_map.json` は、このワールド専用コマンドの識別に必要です。

## 使い方

- Forge 1.20.1、BridgeMOD 1.4.0以上（2未満）、UmetateMod 2.6.23を使います。
- `UmetateMod/build/libs/stackinggame_events-2.6.23.jar` を、サーバーと参加者のMinecraft両方の `mods` に入れます。旧版の同じMODは入れ替えてください。
- サーバーではこのフォルダーをワールドとして読み込みます。シングルプレイでは `.minecraft/saves` にコピーして開けます。
- OP権限またはチートを有効にして下記のコマンドを入力します。サーバーコンソールでは先頭の `/` は不要です。
- 2026-10-25に、指定された `server/Douma_Craft` とMinecraft本体へ導入しました。サーバーは完成MAPのコピーを読み込みます。
- 2026-10-29（埋め立て PR2）から、アプリのゲームの一覧で「埋め立て」を選んで保存すると、UmetateMod がサーバーと Minecraft 本体の両方に入ります（ゲームパック `game-packs/umetate/`）。ギフトの割り当てには18個が並びます。
- 2026-10-29（埋め立て PR3）から、このフォルダーの `umetate_lab_map/` をアプリと一緒に配ります（`npm run prepare:game-maps`。一番上の `playerdata`・`stats`・`advancements` は外す）。
  - ほかのゲームから「埋め立て」に切り替えて保存するたびに、アプリはサーバーの `map_backup/umetate/umetate_lab_map`（配ったものと同じ中身。違えば写し直す）を `haihu_world/umetate_lab_map` へ写し、`level-name` をそこにします。前に遊んだマップは消えます。
  - 埋め立てのまま保存し直したときは、マップに触りません。採掘・サバイバルに切り替えると、マップには触らずに、前に使っていたワールドへ戻します。
  - TOP の「マップを初期化」で、いつでも初期の状態に戻せます（サーバーを止めてから）。遊んでいる途中の3階の作り直しは、今までどおり `/umetate reset` でもできます。

## コマンド

ギフトで動くものは、すべて `/umetate <名前> [回数] [送った人]` の形です（2.6.23。採掘の `saikutu` と同じ形）。例：`/umetate mofumofu 1`、`/umetate nether_army 3 視聴者`。

- 回数は 1〜100000 で、省くと 1 です。送った人の名前は残り全部（空白・日本語・絵文字も可）で、省くと手で打ったものとして扱います。
- 名前は18個です。そうてんもんさんのイベント13個（aquatower・magmatower・aquarium・voidbomb・voidbomb_rain・megablast・nether_army・void_singularity・meteor_shower・meteor_purge・tornado・orbital_laser・shockwave_collapse）と、下の研究室の5つ（otasuke・mofumofu・stamp・atamahuttou・zigoku）です。`reset` は回数を取りません。
- そうてんもんさんのイベントは、待ち行列には1つで入り、回数の分だけ続けて起きます。ほかの人のギフトはそのあとです。`/umetate reset` と `/stackgame cancel` は、残りの回数ごと止めます。死んだときは、残りの回数を続けます（リスポーンを待って起きます）。3階の復元中・地震のあいだに届いても、待ち行列に入れて、終わってから起こします。`/stackgame run <名前>` の形も今までどおり使えます。
- 研究室の5つは、名前ごとの順番待ちに並び、回数の分だけ1秒おきに起きます（列が空なら1回目はすぐ）。黒曜石スタンプと頭沸騰は、毎回その時のプレイヤーの位置をねらうので、追いかけるように落ちます。`zigoku` は何回でも落ちます（いまの地獄が終わってから次）。3階の復元中・地震のあいだは待ちます。`/umetate reset` は順番待ちも捨てます。順番待ちに入った分は「あとN回は順番に起こします」と1行で知らせます。
- 送った人の名前があるときは、始まったときに DisplayMOD でギフトを表示します（ギフトごとに1回、回数と一緒に。そうてんもんさんのイベントは1回目の開始のとき）。`/stackgame run` では表示しません。
- BridgeMOD は1回のコマンドに100回分までしか入れません。250 なら 100・100・50 の3回に分けて打たれます（待ち行列に3つ入り、表示も3回）。

**勝ち**：3階の中央の枠の内側（X・Z −6〜6、Y 49〜64。13×13×16＝2704マス）が、金ブロックとダイヤブロックで1マスの空きもなく埋まると、10 からのカウントダウンが始まります。途中で1マスでも金・ダイヤでなくなると止まり、また埋まると 10 から数え直します。0 で花火・キラキラの粒子・黄緑の「congratulation」のタイトルを出し、枠の中のブロックを全部消します。消す前に、枠の上にいる人にはゆっくり落ちる効果をかけます（16マス落ちて死なないように）。枠の上に積まれた砂などは、消したあと下へ落ちます。`reset` の復元中と地獄のあいだは数えません。枠は岩盤の骨組み（Y 49 と Y 64 の外周、Y 50〜63 は四隅の柱）です。研究室マップでは、イベントの届くアリーナもこの枠の内側（Y 64 まで）になります（設定ファイルの `max-y` によりません）。

`/umetate otasuke` は、オーバーワールドで `fill -6 49 -6 6 56 6 minecraft:gold_block` を実行します。3階の中央枠の内側、13×13×8＝1352ブロックを金で埋めます。実行者が別の階・ディメンションにいても対象は同じです。対象範囲にある別のブロックも金に置き換わります。

`/umetate mofumofu` は、オーバーワールドの X/Z −6〜6、Y 49〜64 にある金ブロックとダイヤブロックを、16色からランダムに選んだ羊毛へ置き換えます。岩盤・空気・既存の羊毛などはそのままです。変換した個数を表示し、対象がなければ0件で終了します。実行する場所によらず3階が対象です。

`/umetate stamp` は、プレイヤーの頭の3ブロック上から縦に黒曜石を3個出し、約1秒の予告後に真下へ落とします。衝突した相手には落下ダメージを与え、着地した黒曜石は障害物として残ります。出現位置に空間がないときは実行しません。`reset` では飛行中のスタンプも終了します。

`/umetate atamahuttou` は、プレイヤーの頭の1ブロック上に溶岩源を出します。溶岩は下へ流れ、自然に広がります。自動では消えません。頭上に既存のブロックがあるときは上書きせず終了します。

`stamp` と `atamahuttou` の対象は実行者です。コンソールからは、オンラインの参加者が1人のときにその人を対象にします。複数人なら `execute as <プレイヤー名> run umetate stamp` のように指定してください。死亡中・スペクテイター、2階の原本内、復元・転送中は実行しません。

`/umetate reset` は、現在の2階を原本として3階を復元します。床下の石・岩盤、内装、空気、収納の中身、コマンドブロックを複製します。3階に追加したブロックは、2階にないものなら消えます。Mobの一掃はしません。既存の妨害イベントと待機列はリセットします。

**復元完了のメッセージが出たら、そのまま次のゲームを始められます。** サーバーの再起動やMinecraftへの入り直しは不要です。復元中だけ妨害イベントの受付を待ち、完了後は自動で再開します。MODのjarを更新したときの再起動とは別です。

2.6.18では、このMAPの自然湧きオフをBridgeMODの固定環境処理より後に適用します。BridgeMODと併用しても、再起動後やリセット後に自然湧きがオンに戻りません。妨害イベントが明示的に呼び出すMobは出現できます。

`/umetate zigoku` は、3階にいる生存中のプレイヤー（スペクテイター以外）を対象にします。約5秒の地震で3階の外壁・回廊が崩れ、白い光が画面を覆っている間に1階へ移動します。1階到着時にウォーデンを合計3体召喚します。実時間5分のボスバーが0になると白い光の中で3階へ戻り、その転送時に召喚分の生存ウォーデンをキルします。参加人数によって3体より増えることはなく、途中で倒した個体は補充しません。ほかのウォーデンは対象外です。

**地獄滞在中も帰還時も、3階は自動復元しません。** 帰還先の床が壊れていれば、床下の岩盤までの範囲で着地場所を探します。復元は `/umetate reset` を実行したときだけです。

退出してもタイマーは進みます。期限後に再参加した場合は3階へ戻します。死亡後にリスポーンした参加者は、期限内なら1階へ戻します。サーバー停止後は、次回起動・参加時に3階へ帰還します。召喚したウォーデンも停止時に片付けます。未読込の個体は再読込時に専用タグで識別して片付けるため、再起動後に残りません。途中で停止した手動リセットだけは、起動後に再実行して完了させます。

処理の二重実行を防ぐため、イベント中の `reset` と `zigoku` の再実行は受け付けません。白い光と揺れのため、参加者側にも新しいUmetateModが必要です。

## 範囲

| 用途 | X / Z | Y | 床の高さ |
| --- | --- | --- | --- |
| 3階・復元先 | −32〜32 | 42〜83 | 48 |
| 2階・原本 | −32〜32 | 0〜41 | 6 |
| 1階・地獄 | −32〜32 | −42〜−1 | −36 |

2階は妨害MODのブロック変更と通常の爆発から保護します。クリエイティブ等で原本を編集すれば、次回の `reset` に反映されます。コピー時点で、3階と2階にはツタの成長や追加物などの差がありました。指定どおり現在の2階を原本にしており、コピー時に3階を上書きしていません。

## 開発時の確認

Forge 47.4.10のサーバーと通常のMinecraftクライアントを接続し、カメラの揺れ、白い光、1階でのカウントダウン、実時間5分後の帰還を画面で確認しました。帰還後も3階の壁は崩れたままです。導入先と確認記録は [実画面での確認記録](visual-check-2026-10-25.md) にまとめています。

`UmetateMod` をビルドしたあと、`labProbeJar` タスクで検証用MODを作れます。このMODは配布用jarには含みません。
`UmetateMod/tools/run-lab-probe.ps1 -Libraries <既存Forgeサーバーのlibraries>` は、完成MAPを使い捨ての別フォルダーへコピーし、実際のForgeサーバーで復元・複数人の転送・タイマー・再参加・再起動を確かめます。ライブラリ元サーバーは停止したままで構いません。ポート25649・18649・18650を使います。

同じ検証で、`mofumofu` の変換範囲・16色・対象外の保持、`stamp` の予告・衝突ダメージ・3個の着地と残存、`atamahuttou` の溶岩源と下向きの流れも確認します。地獄イベントでは、到着時の3体召喚、期限前の生存、帰還時のキル、無関係の個体の保持、停止後に遅れて読み込まれる個体の片付けも検証します。
