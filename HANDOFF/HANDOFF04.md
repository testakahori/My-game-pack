  - 黒曜石とコマンドブロックは、通常の爆発ではもともと壊れない。
  - プレイヤーの採掘は保護の対象外。

#### P2：MODが拒否したイベントを無限に再送してギフトが止まる

- **原因**：コマンドファイル名に日本語や空白があると（`ネコ.txt`、`tnt - コピー.txt`）、BridgeMOD は 400 を返す。Bridge はこれを無限に再送していたため、gift レーンの後続が配信終了まで止まっていた。
- **再送の扱い**：400・404・405・413（P1 で 415 も追加）は再送しない。再送するのは 429・5xx・接続失敗・タイムアウトだけ。送れなかったイベントは次の3か所に記録し、次のイベントへ進む。
  - ログ
  - 操作履歴（`ok:false` と理由）
  - `runtime-status.json` の `delivery`。ダッシュボードに「Modへ送れなかったイベント N件」と直近の理由を出す
- **名前の規則を1か所にまとめた**：規則は BridgeMOD と同じ `[A-Za-z0-9_.-]` で、`bridge/command_files.cjs` に置いた。次の場所で使う。
  - コマンド作成
  - 設定保存
  - テスト発火
  - Bridge の送信前
  - コマンド一覧の `invalidName` の印（表示名はルーレット名やギフト画像に使われるので変えない。画面に印を出すのは UI のテーマで行う）
  - RCON 方式では検査しない
- **保存時の扱い**：エラーにするのは新しく割り当てた使えない名前だけ。保存済みの設定に同じ場所・同じ名前ですでにあるものは警告に留め、ID承認・一括起動・ほかの保存を止めない（レビューの高の指摘への対応）。無効にしてある設定は、Bridge が enabled を見るもの（いいね・シェア/フォロー/訪問/未設定ギフト・コメントギフト）だけ検査しない。
- **Bridge の設定読み込み**
  - Bridge は古い設定に問題があっても起動し、警告を出す。
  - 自動再読込も起動時と同じ検証を通し、エラーのある設定には切り替えない。

- 実ゲーム画面での見た目（美観）の確認は検証対象外だった項目がある。
- 統計の「コイン相当」は実際の受取額への換算ではない。接続中に取得した活動のみ記録される。

## 4. 商用配布に向けた残タスク（#4 より）

## 5. 運用上の注意（HANDOFF03 からの追記・更新）

- **public リポジトリ**なので、パスワード・アカウント ID・RCON パスワード・個人的なやり取りの記録は
  コミットしない。リポジトリ外のローカル専用フォルダ（例: 親ディレクトリ側の作業メモ類）はリポジトリに入れないこと。
- コマンド txt を廃止するときは引き続き `BRIDGE_REMOVED_BUNDLE_FILES` に追記し、割り当ては
  `command_migration.cjs` でバックアップ付き移行する。
- リリース手順は HANDOFF03 末尾の通り（`release/` の .exe / .blockmap / latest.yml をそのままアップロードし、
  ダウンロード URL が 200、アセット名が latest.yml の `path` と一致することを確認）。
- ローカルの作業コピーが origin/main より古い HEAD のまま、ファイルだけ最新になっている状態が起きていた。
  作業開始前に `git fetch` と `git status --short --branch` で HEAD と origin/main の関係を確認すること。
