# BridgeMODとゲーム切替

2026-10-03更新。今回の変更は未公開・未適用です。採掘と要求番号の詳細は[採掘MODと統一コマンド](採掘MODと統一コマンド.md)を参照。

## DOUMAMODからの置き換え

- DOUMAMODのJava処理をBridgeModディレクトリへ移し、MOD IDを`bridgemod`、表示名をBridgeMODに変更。
- ゲーム内コマンドは`/bridge zombie 1`、大技の内部コマンドは`bridgeeffect`。`/bridge`は1.5.0からOP（権限2）だけが使える（中身は権限4で動くため）。
- 視聴者名（1.5.0）：`{ListenerName}` に入る名前は、`"` `'` `\` を全角の `”` `’` `＼` に置き換え、書式コード（`§` と次の1文字）・制御文字・文字の向きを変える制御文字を除き、40文字までにする（`ListenerNames.java`。Bridge 側の `safeDisplayName` も同じ規則）。どの埋め込み方でも壊れず、名前から NBT を書き足すこともできない。txt では他のファイルと同じ `CustomName:"\"{ListenerName}\""` の形で埋め込むこと。
- 強さの上限はない（BridgeMOD 1.7.0、2026-10-11 ユーザーの決定）：送られた数どおりに出す。サーバーが重くなる・落ちるのも妨害のうちで、上限・間引き・消去は入れない。1.5.0 で入れた大技の倍率の上限はなくした。
  - スーパージャンプは1個で32ブロック、重ねた分だけ上がる。高さの上限も低速落下もなく、頂点からは普通に落ちる。頂点を過ぎて水・溶岩・はしご・乗り物・飛行に入ったら、そのジャンプは終わり（次のジャンプは今の位置から数える）。
  - Bridge の運用センターの「個別最大コマンド数」は、Minecraft（BridgeMOD 経由）とテスト発火では使わない。RCON・Telnet で送るゲームの1回あたりのコマンド数の上限としてだけ使う。
  - 暴風雨（storm）は N 個で雷 20×N 回・雨 3分×N（BridgeMOD 1.7.2）。雨が残っているうちに次の暴風雨が来たら、残りに足す（上書きして短くしない）。バニラの /weather clear などで雨が止んだら覚えている終わりの時刻も忘れ、次の暴風雨は今から数える（BridgeMOD 1.7.4）。
  - ルーレットは、送られた回数（ギフトの数×割当の回数など）だけつづけて回す。回すたびに演出して当たりを決める（Bridge・テスト発火とも）。別の人のルーレットとは来た順にまとめて回す（前のルーレットを全部回し終えてから次。デスルーレットも並ぶ。2026-10-12 ユーザーの決定）。当たりは回す直前にその時の設定で決め、途中でルーレットを無効にしたら残りは取りやめる。テスト発火の記録は当選ごとに1行で、画面は手順ごとにまとめて表示する。
  - ダイヤ装備・ネザライト装備（BridgeMOD 1.7.3）は、今着ている防具を消さずに持ち物へ移してから着せる。持ち物に空きがなければ足元に（投げずに）置く。N 個なら N 回着せて N セットぶん手に入る。クリエイティブで持ち物がいっぱいのときは、足元に置いた防具にすぐ触れてしまい、バニラの決まりですぐ消える。サバイバルでは足元に残る（ほかの落ちたアイテムと同じく、5分たつか溶岩・爆発などで消える）。
  - 採掘MOD も 1.1.0 で上限をなくした。TNT大爆発は N 個で半径 N 倍の衝撃波を1回にした（[採掘MODと統一コマンド](採掘MODと統一コマンド.md)）。
- 地形を書き換える大技（流星群の穴・火山・金床など、Java で書き換えるもの）は、保護ブロック・BlockEntity・壊せないブロック（硬さが負：岩盤・バリア・エンドポータルの枠など）を残す（BridgeMOD 1.7.1・採掘MOD 1.1.1、2026-10-11 ユーザーの決定。それまでは岩盤だけ）。txt の `fill`・`setblock` と、採掘MOD の TNT大爆発の頭上の TNT（Java から出すバニラの `fill`）は、この判定を通らない。
- HTTPは`/bridge/event`、`/bridge/exec`、`/bridge/status`。ポートは従来と同じ。変更する場合は`BRIDGE_MOD_PORT`。
- BridgeMOD 1.5.0 から、HTTP と WebSocket はこのPCの Bridge・アプリだけが使える。サーバー起動ごとに乱数トークンを `<サーバーフォルダー>/config/bridgemod-token.txt` に書き、HTTP は `X-Bridge-Token` ヘッダー、WebSocket は `ws://127.0.0.1:<ポート+1>/?token=<トークン>` で送る。次の要求は 403 で拒否する：トークンなし・不一致、`Origin` ヘッダーあり（ブラウザー）、`Host` が `127.0.0.1:<ポート>` / `localhost:<ポート>` 以外。POST の本文は `application/json` に限る（違えば 415）。WebSocket は送信専用（状態・死亡通知）で、受信したイベントは実行しない。アプリは Bridge 起動時に環境変数 `BRIDGE_MOD_TOKEN_FILE` でトークンの場所を渡す。
- BridgeMOD 1.7.6 から（アプリレビュー 2026-10-08 の P5）、状態（プレイヤー・TPS・外部ゲームMODの状態など）はサーバーのスレッドだけで作る。
  - `/bridge/status` は、サーバーに tick と tick の間で作らせて返す。サーバーが 0.25 秒応えないとき（重いとき）は、その場の待ちの件数と最後に作った状態を `"stale":true` 付きで返す（Bridge・アプリの時間切れ 1.5 秒より十分短くする）。
  - HTTP は4本のスレッドで受ける。状態の要求がサーバーを待っている間も、ギフトなどの受付は後ろに並ばない（並ぶと Bridge が時間切れで送り直し、ギフトが2回実行される）。
  - 外部ゲームMODの状態は MOD ごとに JSON にする。JSON にできない MOD の分だけ `{"ok":false,"error":…}` になる。
  - WebSocket は、接続ごとの送信スレッドと送信待ち（256件まで）で送る。tick は送信待ちに積むだけで、送り終わるのを待たない。読まずに送信待ちがあふれた接続は切る（Bridge はつなぎ直す）。65,535 バイトを超えるメッセージも送れる。
- BridgeMOD 1.8.0 から（2026-10-16 ユーザーの決定。アプリレビュー 2026-10-08 の P6 の残り）、妨害を一時停止できる。
  - `/bridge/control` に `{"action":"pause"}`・`{"action":"resume"}` を送る（トークンが必要）。止めている間は、待ちから取り出して実行することだけを止める。受付は続け、待ちに積む。待ちがいっぱいなら 429（Bridge が預かって送り直す）。
  - 始まっている演出・固定環境・状態の送信は続ける。状態に `"paused"` が出る。止めている状態はメモリだけで、サーバーを止めると解ける。
  - アプリは配信ホームのボタンで止め、止めている間はどのページにも帯を出す。
- アプリ・BRIDGE・コマンド一覧・同梱txtも新名称を使用。旧`/douma`コマンドと旧HTTP入口は登録しない。
- 旧設定の`douma_mod`・`doumaModHost`・`doumaModPort`は読み取り互換を維持する。旧MODを起動する意味ではない。
- ワールド中の既存Mobタグ・天候の保存ファイル名は互換のため維持する。
- ギフト600／いいね120／その他280の別キュー、60コマンドのtick予算といいね8予約枠、Java効果の生成予算を引き継ぐ。

## 固定環境

暗視・アイテムロストなし・昼・晴れはBridgeMODが維持する。設定スイッチは設けない。アプリを開いていない場合もサーバー側で適用される。

`sendCommandFeedback false`と`commandBlockOutput false`も固定する。コマンドの実行通知とコマンドブロックの出力を非表示にし、手動で変更されても固定値へ戻す。

敵モブだけ自然発生を禁止する。ForgeでMONSTERに分類されるMobの自然発生・チャンク生成時の出現・巡回隊・増援を止め、村への自動ゾンビ襲撃も止める。ファントムの自然発生も対象。牛・羊・魚を残すため、`doMobSpawning true`を固定し、敵だけを出現理由で判定する。ピースフルへの変更は行わない。既に存在するMob、スポナー、スポーンエッグ、ギフト・コマンド・ゲームMODが意図的に召喚するMobは対象外。ゲームMODでの意図的な召喚にはNATURAL等を使わず、COMMAND・EVENT等を使用する。

流星群の夜、暴風雨など、BridgeMODのイベントが持つ一時変更は優先する。終了後は昼・晴れへ戻る。参加・効果解除後に暗視を再付与する。

アプリからの`_gamerules.txt`実行と暗視データパック生成は停止。旧NightVision_Packはサーバー停止中にワールドの`.mygamepack-retired-packs`へ退避し、削除しない。古いMAPを復元してパックが戻っても、次の起動前に同じ処理を行う。

「固定」は製品UIと通常運用のルール。サーバー所有者によるjar改造や管理用コマンド入力そのものを禁止するセキュリティ機能ではない。

## ゲームを選ぶ

配信ホーム・ギフト設定・コマンド一覧の上部でゲームを選ぶ。

| 選択 | 両方のmodsフォルダに配置するもの | 選べるコマンド |
|---|---|---|
| 採掘 | BridgeMOD＋DisplayMOD＋saikutuMOD | 共通＋採掘の16コマンド |
| 埋め立て | BridgeMOD＋DisplayMOD＋UmetateMOD | 共通＋登録された埋め立てのコマンド |
| RUN | BridgeMOD＋DisplayMOD＋RunMOD | 共通＋登録されたランのコマンド |

ゲームを選んで「保存」するまでは、一括起動・BRIDGE の起動・ギフト設定は使えない（最初は「選んでください」と出る）。サバイバルは選択肢に出さない（2026-10-29）。

どのゲームでも、サーバーの mods には OBSMOD も配置する（Minecraft 本体には配置しない）。

BridgeMODとDisplayMODは全ゲームの標準装備。アプリでの切替には両方のjarが必要。OBSMOD（MOD ID `minecraft_obs_bridge`）も標準装備だが、サーバーにだけ入れる（Minecraft 本体には入れない。2026-10-25）。OBS ツールへ送るのは、サーバーの `config/minecraft_obs_bridge/obs-send.properties` で `enabled=true` のときだけ（無ければ送らない）。オン・オフと送り先は、運用センターの「動作設定」の「OBS 連携」で決める。アプリがこのファイルを、保存したときと、アプリからサーバーを起動するたびに書き直す（OBSMOD は起動のときに読むので、サーバーが動いている間の変更は次の起動から効く）。独立APIは表示MODが欠けた場合もゲーム本体を止めない。APIと表示タイミングは[DisplayMOD連携ガイド](DisplayMOD連携ガイド.md)を参照。

UmetateMOD・RunMODの本体はまだ存在しないため、初期状態は「未導入」。ゲームパックを登録するまで切り替えられない。実ゲームのAPI・コマンドは未確定であり、架空の呼び出し仕様を製品へ組み込んではいない。

選択欄だけの変更ではファイルを入れ替えず、「このゲームに切り替える」で適用する。

- サーバー、BRIDGE、Minecraft本体とランチャーが停止していることを確認。
- サーバー側はアプリで選んだサーバーフォルダ。Minecraft側は既定でユーザーの`.minecraft`。別の起動構成のゲームディレクトリを使う場合は「Minecraftの保存先を選ぶ」で指定。
- 現在のmodsフォルダは丸ごと各保存先の`.mygamepack-mod-switch/<処理ID>/previous`へ退避。新しいmodsには必要なjarだけを配置する。他のMODも削除しない。
- 両側のコピーを準備・照合してから入れ替える。片側失敗は両側を戻す。アプリが途中終了した場合は次回「切替前の状態に戻す」で復旧するまで起動を止める。
- ギフト割り当て、いいね、各イベント・ルーレット設定をゲームごとに保存・復元。初めて選ぶゲームの割り当ては空から開始（採掘のみ、採掘へ移したコマンド（16件）が割り当てに残っていれば、そのプロフィールの割り当てを引き継ぐ。すでに採掘の設定があるときは上書きせず、外した割り当ては退避に残る。他のゲーム専用のコマンドは写さない）。アカウント・RCON・配信統計は共通のまま保持。
- MAPそのものの保存・ロード・変更は行わない。
- アプリを更新したあと（手動インストールは初期セットアップを終えたとき、それ以外は起動時）、今選んでいるゲームの MOD の jar だけを両側で新しい版に入れ替え、ゲームのコマンドも新しくする（`game_profiles.refreshMods`・`electron/game_mods_refresh.cjs`、2026-10-13 ユーザーの決定）。「保存」と違って mods を丸ごと退避せず、ほかの MOD やファイルには触らない。アプリが置く MOD かは jar の中の MOD ID（bridgemod・doumacmd・displaymod・minecraft_obs_bridge・ゲームMOD）で見分け（OBSMOD はサーバーにだけ入れ、Minecraft 本体にあれば外す）、入れ替えた古い jar は `.mygamepack-mod-switch/<処理ID>/replaced` へ退避する。途中で失敗したら両側を元に戻す。設定（割り当て）は書き換えない。止まっていないなどで入れ替えられなければ何も変えず、次の起動でもう一度試し、ホームに「アプリの更新でMODが古いままです」と理由と「今すぐ入れ替える」ボタンを出す（同じ入れ替えをもう一度試す。「保存」しても消えるが、そちらは mods を丸ごと退避する）。コマンドを書けなかったときも MOD ごと元に戻し、戻せなかった分があればそう伝える。同じ名前でもアプリの MOD と分からないファイルは、上書きせずに退避する。まだ一度も「保存」していないときは何もしない。済んだ版はアプリ設定の `gameModsVersion` に残る（開発版では書かない）。手で登録したゲームパックがあるときは、同梱より登録したパックが使われる（前からの決まり）。

## ゲームMOD完成後の登録形式

配布フォルダに`game.json`とjarをまとめ、「ゲームパックを登録」でフォルダを選ぶ。

```json
{
  "format": 1,
  "id": "umetate",
  "modId": "umetatemod",
  "serverJar": "UmetateMod.jar",
  "clientJar": "UmetateMod.jar",
  "commands": []
}
```

これは形式の例。jar名・modIdは完成したMODに合わせる。`run`の場合はidを`run`にする。両側共通のjarならserverJarとclientJarは同じでよい。登録時にjar内のMOD IDも照合する。

`commands`の各項目：

| 項目 | 内容 |
|---|---|
| key | 小文字英数字・アンダースコアの一意な識別子 |
| title | ギフト設定で表示する日本語名 |
| command | ゲームMODが実装したMinecraftコマンド1行。先頭の`/`は省略可 |
| commonDisplay | 任意のboolean。即時イベントでBridgeMODから共通表示を出す場合のみtrue。省略・falseはゲーム側が実開始時に表示 |

commandには`{Count}`・`{ListenerName}`・`{RequestId}`を使用できる。キーは`game_umetate_<key>.txt`等に分離する。既定ではBridgeMODはゲーム側に渡す前の共通タイトルを出さない。DisplayMODの独立APIを用意済み。ゲームMODが実際に開始するときの呼び出しは、各ゲームMODの完成時に接続・検証する。OBSMODは `ObsMod/` に取り込み、標準装備として同梱した（2026-10-25）。

プレイヤーの入力は全ゲームで `/bridge <key> <count>`。Java受付APIは`bridgeEventApi: 1`で選択でき、要求番号・名前・個数をMapで受け取る。詳細は採掘MODの連携ガイドを参照。ゲームMOD内の待機列・処理上限・実開始通知の実装まで自動的に完成するものではない。

ゲームMODに追加の必須ライブラリMODがある場合は別途対応が必要。現在の配布形式はBridgeMOD・DisplayMOD・OBSMOD（サーバーだけ）・ゲームMODの構成を対象とする。

## 検証と公開

ゲーム切替の成功・未導入・不正ファイル・停止条件・片側失敗の巻戻し、既存アプリの回帰テスト、BridgeMODのビルド、専用MinecraftサーバーとUIの操作を確認する。

UmetateMOD・RunMODとの実連動は、完成した本物のjarを使うまで未検証。アプリの更新はユーザーからの更新依頼後に行う。

## Minecraftの保存先を探す

ホームの「Minecraftの保存先を探す・MODの保存先を確認」から「Minecraftの保存先を自動検出」を押します。標準の `%APPDATA%/.minecraft` と、標準・現在の保存先にある公式ランチャーの `launcher_profiles.json`／`launcher_profiles_microsoft_store.json` を確認します。ドライブ全体の走査やAIは使いません。

起動構成名・バージョン・実際の保存先を見て選び、「この保存先を使う」で記憶します。Forge 1.20.1の構成が見つかった候補には目印を表示しますが、自動決定はしません。MODの実配置は、Minecraft・ランチャー・サーバー・BRIDGEを停止してから「このゲームに切り替える」で行います。

消えた保存先は理由付きで選択不可にします。サーバーと同じ場所や親子関係の場所、modsがリンクになっている場所も選べません。検索・選択だけでフォルダーを作成したり、MOD・MAP・ランチャー設定を変更したりしません。公式ランチャー以外や、別の場所にあるランチャー設定は「手動で指定」を使ってください。
