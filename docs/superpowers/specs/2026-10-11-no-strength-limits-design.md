# 強さの上限をやめる・TNT大爆発の衝撃波 設計書

- 日付：2026-10-11
- 対象：BridgeMOD 1.6.1 → 1.7.0、SaikutuMOD 1.0.3 → 1.1.0、BRIDGE（`bridge/index.js`）、アプリ（運用センターの表示とテスト発火の案内）
- 状態：ユーザーと会話で合意した内容。実装計画はこの設計書の確認後に作る。

## 1. 目的と方針（ユーザーの決定）

2026-10-10・11 にユーザーが決めた方針。P4（2026-10-09、PR #49）で入れた強さの上限を外す。

- 制限は一切なし。送られたギフトの数どおりに妨害を出す。お客さんは「100個送ったら100回分起きて配信者が慌てる」のを期待して送る。
- 数を増やしてサーバーを落とそうとするのも妨害の醍醐味。落ちたら立て直す。自動再起動などの仕組みは作らない。負荷対策として、上限・間引き・消去は入れない。
- 鶏やゾンビを古いものから消す仕組みは作らない。
- TNT大爆発は、N 個送られたら「半径が N 倍の大爆発を1回」起こす。
  - 頭上に並べる TNT（約7,400個）は今のまま、N に関係なく1回分（2026-10-11、重さを伝えたうえで決定）。
  - 爆発のあと、爆心から衝撃波が広がって地形をえぐる。広がっていく見せ方にする。速さは毎秒40ブロック（2026-10-11）。
  - えぐる穴は、今の穴を横も深さも N 倍にした形（2026-10-11）。
  - えぐるのは読み込まれている地形だけ（配信に映る範囲）。遠くの地形を生成して削る作りや、近づいたら削る作りにはしない。岩盤は残す。
  - 衝撃波に巻き込まれたモブ・プレイヤーは、爆発と同じくダメージを受けて吹き飛ぶ。
  - 削ったブロックはアイテムにしない。
- スーパージャンプは高さの上限を外し、低速落下も付けない（2026-10-11。落下死してよい。問題は落ちてくる時間）。
- BRIDGE の「個別最大コマンド数」は、Minecraft（BridgeMOD 経路）では掛けない。RCON・Telnet で送るゲーム用には残す（2026-10-11）。
- `/bridge` コマンドを OP（権限2）に限った変更はセキュリティのためなので残す。

## 2. 今の状態

### 上限がかかっている場所

| 場所 | 中身 |
|---|---|
| `BridgeMod/.../EffectLimits.java`（`GiftEffects.start` の `clamp`） | 大技の count：鶏・矢・金床・メテオ・流星群・火山は3、ゾンビウェーブは2、スーパージャンプは10 |
| `EffectLimits.JumpChain`（`GiftEffects.jump`） | スーパージャンプは、連続ジャンプを始めた高さから 320 ブロック上まで。低速落下を付け、着地まで切らさない |
| `SaikutuMod/.../SaikutuLimits.java`（`SaikutuEffects.start` の `effectCount`） | 洪水・氷河期は3、天変地異は2 |
| `SaikutuLimits.scriptRepeat`（`SaikutuMod.offer`） | txt のくり返し：TNT大爆発・地割れ・溶岩地獄・落とし穴・ランダムワープは3、ピッケル没収は1、ほかは200 |
| `bridge/index.js` の `limitEventCount`（`bridgeEventDelivery` の `maxCount`） | BridgeMOD へ送る共通イベントの count を「個別最大コマンド数」（既定200）で抑える。ゲーム MOD 向けは抑えない |

上限ではないもの（今回は変えない）

- BridgeMOD の `MAX_COUNT=100`：まとめて実行する大技（`COUNT_MODE: aggregate`）を100ずつに分けて渡すだけで、残りは次に回す。総数は減らない。
- BridgeMOD・SaikutuMOD の count の範囲の確認（1〜100,000）：入力の確かめで、強さの上限ではない。
- 各キューの長さ（ギフト600件など）：満杯の間は BRIDGE が手元に持ったまま再送するので、捨てない。

### 今の TNT大爆発（`SaikutuMod/src/main/resources/commands/tntdaibakuhatu.txt`）

```
execute at @p if block ~ ~30 ~ air run fill ~7 ~37 ~-7 ~-7 ~5 ~7 minecraft:tnt
execute at @p if block ~ ~30 ~ air run fill ~ ~4 ~ ~ ~4 ~ minecraft:redstone_block
execute at @p unless block ~ ~30 ~ air run summon tnt ~2 ~ ~ {Fuse:40}
（同じ形で ~-2 ~ ~、~ ~ ~2、~ ~ ~-2）
```

- 1行目で頭上 5〜37 ブロックに TNT（15×33×15＝7,425個）を敷き詰める。2行目は、1行目で `~ ~30 ~` が TNT になるので実際には動かない。3〜6行目が足元に点火済みの TNT を4個出し、2秒後の爆発で頭上の TNT に連鎖する（頭上が空いていないときは、足元の4個だけ）。
- count=1 の実測（2026-10-11、使い捨てのサーバー。石の台は半径48・高さ64）
  - 穴は、半径25まで深さ9〜11、半径30〜36で深さ7〜8、半径40で6、半径44〜48で4のお椀形。測った台の端（半径48）まで地面が下がっていた。
  - TNT は10分たっても爆発し終わらず、その間ずっとサーバーは処理が追いつかない状態だった。

## 3. 設計

### 3.1 TNT大爆発（SaikutuMOD 1.1.0）

TNT大爆発を、txt のくり返しから採掘の大技（`SaikutuEffects.KEYS`）に移す。N は1回の要求でまとめて受け取る（洪水などと同じ）。`tntdaibakuhatu.txt` は表示名などのメタ情報（`# TITLE` など）だけを残す。

1. **頭上の TNT と足元の TNT**：今の txt の6行と同じコマンドを、プレイヤーを実行者にして、N に関係なく1回だけ実行する。見た目と重さは今と同じ。
2. **衝撃波**：発動から40 tick（2秒）後、足元の TNT が爆発するときに始める。爆心は、発動したときのプレイヤーの足元のブロック。

#### 衝撃波の形

- 爆心を中心にした楕円体。横の半径 `R = 48 × N`、上下の半径 `D = 11 × N`（ブロック）。
- 位置 (dx, dy, dz) の正規化した距離 `s = sqrt((dx² + dz²) / R² + dy² / D²)`。`s ≤ 1` の範囲をえぐる。
- 爆心より上も、同じ楕円体の分だけえぐる（爆発で吹き飛ぶのと同じ）。
- N=1 で今の穴と同じ大きさになる。実測の深さ（半径25で9〜11、36で7〜8、44で4）と、この楕円体の深さ（9.4、7.3、4.4）はほぼ一致する。
- N=2 で半径96・深さ22、N=4 で半径192・深さ44。岩盤（地表が y=64 なら128ブロック下）に届くのは N=12 くらいから。

#### 衝撃波の広がり方

- 横に毎秒40ブロック（1 tick に2ブロック）。正規化した距離でいうと、1 tick ごとに `s` の上限が `2 / R` ずつ増える。
- 各 tick では、前の tick の `s` から今の tick の `s` までの殻だけをえぐる。
- 1 tick に空気へ変えるブロックの数に上限（予算）を設ける。予算を使い切ったら、その殻の残りから次の tick に続ける。重いときは波が少し遅れるが、えぐる範囲は削らない。
  - 予算は衝撃波専用に、全部の衝撃波で合わせて 1 tick 50,000 ブロックから始め、実機テストで調整する。既存の採掘の大技の予算（1 tick 384 ブロック）は使わない。それだと N=4 の穴（約680万ブロック）に15分かかり、毎秒40ブロックで広がらないため。
  - 数えるのは実際に空気へ変えたブロックだけ（もともと空気の位置は数えない）。
- 1 tick に調べる範囲は、今の横の半径の内側の列だけにする。列ごとに、殻に入る上下の範囲を式で求める（箱の中を全部調べない）。

#### えぐる範囲の制限（読み込まれている地形だけ）

- 横は、爆心から `(サーバーの描画距離 + 2) × 16` ブロックまでしか調べない。その外は、そもそもチャンクが読み込まれていない。
- 書き換えは、既存の `SaikutuEffects.set()` と同じ判定を通す。
  - 読み込み済みのチャンク・建築できる高さの中だけ
  - `BlockProtection.canModifyBlock`（コマンドブロック3種は残す）
  - BlockEntity のある位置は飛ばす（チェストなどは残る）
  - 岩盤は残す
- 空気へ変える。ブロックのアイテムは落とさない。周りへの通知は今の `set()` と同じ（水や砂は流れ込む・落ちる）。

#### 巻き込まれたモブ・プレイヤー

- 波の先端が通った生き物（`LivingEntity`）の位置で、地形を壊さない爆発（`ExplosionInteraction.NONE`、威力4）を起こす。ダメージを受けて吹き飛ぶ。1回の衝撃波で、同じ生き物は1回だけ。
- 見た目と音のため、先端の輪の上でも地形を壊さない爆発を、1 tick に最大16か所、場所を変えながら起こす。

#### 同時に起きたとき

- TNT大爆発がいくつ届いても、届いた順に1回ずつ、それぞれの N で起こす。衝撃波は同時にいくつ進んでもよい（予算は全部の衝撃波で分け合う）。
- サーバーを止めると、進行中の衝撃波は捨てる（ほかの大技と同じ）。

### 3.2 上限を外す

#### BridgeMOD 1.7.0

- `EffectLimits` クラスをなくし、`GiftEffects.start` は count をそのまま使う。
- スーパージャンプ
  - 目標の高さは、今の目標に `32 × count` を足すだけ。上限はない。
  - 上昇は今と同じく、サーバー側で1 tick 最大3.2ブロックずつ持ち上げる。上昇中は落下の距離を0にする（今と同じ）。
  - 低速落下は付けない（跳んだときも、着地までの間も）。頂点からは普通に落ちる。高ければ落下死する。
- 契約テスト `EffectLimitsContractTest` はなくす。

#### SaikutuMOD 1.1.0

- `SaikutuLimits` クラスをなくす。`SaikutuEffects.start` は count をそのまま使い、`SaikutuMod.offer` はくり返し回数を抑えない。
- 契約テスト `SaikutuLimitsContractTest` はなくす。

#### BRIDGE とアプリ

- `bridge/index.js`：BridgeMOD へ送るとき（`bridgeEventDelivery`）は `limitEventCount` を掛けない。RCON・Telnet で送るとき（`commands.slice(0, maxCommandsPerGift)`）はそのまま残す。
- 運用センター（`src/components/OperationsPage.tsx`）：「個別最大コマンド数」の欄に「Minecraft（BridgeMOD）では使いません。RCON・Telnet で送るゲームの、1回あたりのコマンド数の上限です。」と添える。
- アプリのテスト発火の案内（`electron/main.cjs`）で、Minecraft の回数が抑えられると表示している箇所を、抑えない表示にそろえる。
- `electron/test/bridge-count-limit.test.cjs` は、「BridgeMOD 経路では抑えない・RCON 経路では抑える」に書き換える。

## 4. 版と互換性

- BridgeMOD 1.7.0（振る舞いが変わる）。SaikutuMOD 1.1.0（大技が増える）。SaikutuMOD の `mods.toml` の bridgemod は `[1.6.0,)` のまま（新しい API は使わない）。
- `game-packs/saikutu/game.json` の jar 名を 1.1.0 にそろえる。
- 既存の利用者は、ホームで採掘を選び直すまで古い SaikutuMOD のままになる（アプリの更新で入れ替わるのは BridgeMOD・DisplayMOD だけ）。リリースノートで案内する。

## 5. テスト

1. 契約テスト（Minecraft に依存しない。CI の mod-build）
   - 衝撃波の形と進み方を、純粋な Java のクラス（例：`SaikutuMod/.../Shockwave.java`）に分ける。
     - N=1・2・4 の `R` と `D`。
     - `s` の計算と、楕円体の内側かどうか。
     - 1つの列について、tick の殻に入る上下の範囲。
     - 1 tick で `2 / R` ずつ進み、`R / 2` tick ほどで端に届くこと。
     - 横の調べる範囲を、描画距離から決める制限。
     - N=1 の深さが実測と合う：半径25で9〜10、36で7〜8、44で4〜5。
   - スーパージャンプの目標の高さ（上限なし）。
2. 配線のテスト（`npm run verify`、ソースの照合）
   - `EffectLimits`・`SaikutuLimits` への参照がない。
   - `GiftEffects` に `SLOW_FALLING` がない。
   - TNT大爆発が `SaikutuEffects.KEYS` にあり、`set()` を通してえぐる。
   - BRIDGE の BridgeMOD 経路が `limitEventCount` を通らない。
3. BRIDGE とアプリのテスト：`bridge-count-limit.test.cjs` の書き換え、テスト発火の案内。
4. 実機テスト（使い捨ての Forge サーバー）
   - スーパージャンプ count=20：640ブロック前後まで上がり、低速落下が付かない。
   - TNT大爆発 count=1・2：衝撃波が終わったところで穴の半径と深さを測る。N=2 は半径96前後・深さ22前後。頭上の TNT の連鎖は重いので、衝撃波だけを先に測る（半径48より外は、頭上の TNT の影響を受けにくい）。
   - 衝撃波の範囲にあるコマンドブロックが残る。
   - 天変地異・洪水などの大技が、大きな count でもそのまま実行される（上限で抑えたログが出ない）。
5. 開発版のアプリで、ユーザーと確かめる（退避 → 確認 → 復元）。

## 6. PR の分け方

1. BridgeMOD 1.7.0 ＋ BRIDGE ＋ アプリ：`EffectLimits` をなくす、スーパージャンプ、「個別最大コマンド数」の扱い。
2. SaikutuMOD 1.1.0：`SaikutuLimits` をなくす、TNT大爆発の衝撃波。

## 7. 今回やらないこと

- 頭上の TNT を減らすこと（ユーザーの決定で今のまま）。
- 負荷を下げる仕組み（間引き・消去・自動再起動）。
- 遠くの地形を生成して削ること、近づいたら削ること。
- `tntdaibakuhatu.txt` の2行目（赤石ブロック）が動かない件の修正。今の見た目を変えないため、そのまま同じコマンドを実行する。
