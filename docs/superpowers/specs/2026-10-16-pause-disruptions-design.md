# 妨害の一時停止 設計書

2026-10-16。アプリレビュー（2026-10-08）の P6 の残り「サーバーを動かしたまま妨害の受付だけ止める手段がない」を直す。

## 1. 目的と方針（ユーザーの決定）

- 使う場面は、配信中の休憩や準備の間だけ妨害を止めて、再開したら続きを起こすこと（「休憩・準備の間だけ止める」）。
  - 溜まった分を捨てるボタンは作らない。レビューの「待ち列を破棄」は、今回の目的に要らない。
- 止めている間に届いたものは、ギフトもいいねも全部預かる。再開したら、送られた数どおり起こす（「全部預かる」）。
  - 長い休憩のあとは、再開したあとに続けて起きる。ただし BridgeMOD の速さ（1 tick に最大60コマンド）で順に起きるので、一度には起きない。
  - 10-11 の方針「強さの上限は設けない・送られた数どおり出す」、10-14 の決定「ギフトは捨てない」と合う。
- 止める場所は BridgeMOD（「案A：BridgeMOD で止める」）。始まっている演出は最後まで続け、テスト発火も一緒に止め、サーバーの再起動で解ける。

## 2. 今の状態

- 停止の手段は、一括停止・BRIDGE停止・サーバー停止だけ。止める対象が動いているときは確認を出し、ゲームが未保存のときも停止パネル（`StopPanel.tsx`）を出す（10-09 に直した P6 の一部）。
- BRIDGE を止めても、BridgeMOD の待ち（ギフト600・いいね120・そのほか280件まで）は実行され続ける。
- BridgeMOD 1.7.5 から `/bridge/control` がある。今は `{"action":"discard","type":"like"}`（配信終了でいいねの待ちを捨てる）だけを受け付け、ほかは 400 を返す。
- 妨害の入口はどれも BridgeMOD の待ちを通る：BRIDGE からのギフト・いいね・そのほか（`/bridge/event`）、ルーレットの演出（`/bridge/exec`）、アプリのテスト発火（`mod:testEvent` → `/bridge/event`）、ゲーム内の `/bridge <key> <count>`（`runKey`）。
  - 通らないのは、OP が演出を直接試す `/bridgeeffect` だけ。
- アプリは `/bridge/status` を `mod:status` で読む。画面上部は5秒ごと（`App.tsx`）、運用センターは2秒ごと。
- 停止は出どころ付きで `logs/stop-requests.log` に残る（`electron/stop_requests.cjs`）。

## 3. 設計

### 3.1 BridgeMOD 1.8.0

- 一時停止の状態は `private volatile boolean paused` に持つ。メモリだけで、ファイルには残さない。
  - サーバーを止めるとき（`onServerStopping`）に false へ戻す。サーバーを再起動すると、止めていない状態で始まる。
- `/bridge/control` に2つの指示を足す（トークンが必要なのは今と同じ）。
  - `{"action":"pause"}`：`paused = true`。返すのは `{"ok":true,"paused":true}`。
  - `{"action":"resume"}`：`paused = false`。返すのは `{"ok":true,"paused":false}`。
  - どちらも、すでにその状態でも 200 を返す（2回押しても困らない）。
  - ログに `[Bridge] disruptions paused` / `[Bridge] disruptions resumed` を出す。
  - 今の `discard`・`like` はそのまま。それ以外は今までどおり 400。
- 止めている間の tick：
  - 待ちから取り出して実行する処理（`processQueues`）だけを飛ばす。
  - 始まっている演出（`giftEffects.tick`）、いいねのタラの数え方（`likeCod.tick`）、固定環境（`environment.apply`）、状態の送信（1秒ごと）は続ける。
  - ゲームMODへ渡すのも待ちの処理の中なので、一緒に止まる。ゲームMOD自身の待ちにすでに入った分は、ゲームMOD側で動く。
- 受付（HTTP）は止めない。止めている間も待ちに積む。
  - 待ちがいっぱいなら、今までどおり 429 を返す。BRIDGE は自分のところで預かって、空くまで送り直す（`createModEventDelivery` の再送。上限なし）。
  - 配信終了でいいねの待ちを捨てる動き（10-14）は、止めている間も同じ。
- ゲーム内の `/bridge <key> <count>` は、止めている間も待ちに積む。実行した人には「[Bridge] 妨害は一時停止中です。再開すると実行されます」と出す。
- 状態の JSON に `"paused":true/false` を足す。
  - 待ちの件数と同じく `statusHead` に入れる。サーバーで作った状態にも、古い状態（`"stale":true`）にも入る。
  - WebSocket の状態にも入る。

### 3.2 アプリ

- main と preload に `mod:pause(origin)`・`mod:resume(origin)` を足す。
  - BridgeMOD の `/bridge/control` へ送る（`requestBridgeMod`）。
  - 返すのは `{ ok, paused }`。失敗したときは理由を返す。BridgeMOD が 1.8.0 より前で 400 になったときは「BridgeMOD を新しくすると使えます（1.8.0 以上）」とする。
  - 出どころ付きで `logs/stop-requests.log` に残す（`stop_requests.cjs` の対象に「妨害の一時停止」「妨害の再開」を、出どころに「配信ホームの一時停止」「配信ホームの再開」「一時停止の帯の再開」を足す）。
- 配信ホームの操作盤（`DashboardPage.tsx` の BRIDGE の操作の近く）に「妨害を一時停止」ボタンを置く。
  - 止めている間は「妨害を再開」に変わる。
  - 押せるのは BridgeMOD とつながっているときだけ。止めても戻せるので、確認は出さない。
- 止めている間は、どのページでも上部（`App.tsx` の未保存の帯と同じ場所）に帯を出す。
  - 文言：「妨害を一時停止中です。届いた分は預かっています（ギフト N・いいね N・そのほか N）。再開すると順に起きます」。N は BridgeMOD の待ちの件数。BRIDGE で預かっている分は数えない。
  - 帯にも「再開」ボタンを置く。止めたまま忘れないようにするため。
  - 状態は画面上部の5秒ごとの `mod:status` から読む。ボタンを押したあとは、すぐ読み直す。
- テスト発火（`mod:testEvent`）：止めている間に押したときも待ちに積み、結果に「一時停止中です。再開すると実行されます」を足す。止めているかは、送る前に `/bridge/status` を読んで判断する。

### 3.3 BRIDGE

変えない。止めている間も今までどおり送り、待ちがいっぱいなら預かって送り直す。

## 4. 版と互換性

- BridgeMOD を 1.8.0 にする。アプリとBRIDGE は、BridgeMOD 1.7.x でも今までどおり動く。一時停止のボタンを押したときだけ「BridgeMOD を新しくすると使えます」と出す。
- アプリを更新すると、BridgeMOD は自動で入れ替わる（PR #91）。
- ゲームMOD連携 API は変えない。説明に「止めている間は、ゲームMODへ渡さない」と書き足す。

## 5. テスト

- 実機（使い捨てのサーバー、`BridgeMod/test/pause.cjs` を新しく作る）。
  - 止めると、ギフト・いいね・そのほか・`/bridge/exec`・ゲーム内の `/bridge` が実行されない（スコアボードで数える）。待ちの件数は増え、状態の `paused` は true。
  - 再開すると、送った数どおり実行される。
  - 止めている間に、待ちがいっぱいなら 429 を返す。
  - 始まっている演出（たとえば複数 tick 続く演出）は、止めても最後まで続く。
  - 2回止めても、2回再開しても 200。
  - 直す前の確認：BridgeMOD 1.7.6 では `pause` が 400 になる。
- アプリ：
  - `mod:pause`・`mod:resume` が `/bridge/control` へ正しい本文を送り、`stop-requests.log` に出どころ付きで残す。古い BridgeMOD の 400 で「新しくすると使えます」を返す。main を読み込む試験台を使う。
  - テスト発火の結果に、止めている間の文言が付く。
  - 帯とボタンの表示の判断（止めているか・つながっているか）は、純粋な関数に分けてテストする。
- ソースを読むテスト：tick で `paused` のときに `processQueues` を呼ばないこと、`statusHead` に `paused` が入ること、版が 1.8.0 以上であること。
- `npm run verify`、`scripts/test-bridge-contracts.cjs`、CI の mod-build（JUnit）。

## 6. PR の分け方

1つの PR にする（BridgeMOD 1.8.0 とアプリ）。BRIDGE は変えない。

## 7. 今回やらないこと

- 溜まった待ちを捨てるボタン（ユーザーの決定）。
- 一時停止をファイルに残して、サーバーの再起動のあとも続けること。
- BRIDGE で預かっている件数の表示。
- `/bridgeeffect`（OP が演出を直接試す命令）を止めること。
- 止めている間だけテスト発火を動かすこと（待ちの分け方が増えるため。ユーザーの決定で一緒に止める）。
