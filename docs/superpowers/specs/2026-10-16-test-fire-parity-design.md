# テスト発火を本番と同じ処理にする（設計書）

- 日付: 2026-10-16
- 出どころ: アプリレビュー 2026-10-08「テスト発火と本番の食い違い」（HANDOFF04 の9番、残っている大きい問題）
- ユーザーの決定（2026-10-16）
  - 使い道: 本番と同じ結果を確かめる。BRIDGE が動いていることを前提にしてよい
  - 作り方: 案A。テスト発火も BRIDGE に渡し、本番と同じ処理を通す
  - 設計: 下の内容でよい

## 1. 目的

テスト発火で見た結果を、配信中に同じことが起きたときの結果と同じにする。
今はテスト発火を electron/main.cjs と electron/event_tests.cjs が、本番を bridge/index.js が別々に作っている。そのため次の食い違いがある。

| 食い違い | 本番（BRIDGE） | 今のテスト発火 |
|---|---|---|
| いいねの追いつき上限 | BridgeMOD 経路では掛けない | 5回で打ち切る |
| アナウンス | 100未満のいいね・訪問は出さない。マイルストーン・コンボ・投票は必ず出す | 設定どおり全部に出す |
| 順番 | いいね・フォローのマイルストーンが先、ルール・フォローの設定があと。コメントコマンドが先、コメントギフトがあと | 逆 |
| ルーレットの当たりの種類 | type は other、履歴の種類は roulette | 元のイベントの種類のまま |
| 送り方 | 再送・100回ずつの分割・requestId・送る列 | 1回だけ送る。混んでいる（429）と失敗 |
| GAME_MOD の回の番号 | 送る列に入れた時点で決める | 送る直前に読む |
| 送り主の名前 | 整えた表示名（safeDisplayName） | 40文字で切るだけ |
| ミュートの照合 | ID・名前・整えた表示名 | 入力した名前だけ |
| 設定 | options は BRIDGE の起動時の値 | 毎回ファイルから読む |
| ギフト N 個 | 連打として1個ずつ処理する | 1回にまとめて N 倍 |

## 2. 全体の流れ

```
画面（EventTestPanel）
  └ api.testEvent(入力)            … 今と同じ
main（mod:testEvent）
  ├ BRIDGE が動いていない → 「BRIDGE を起動すると試せます。」で終わり
  ├ 送るとき: BridgeMOD の状態を読む（一時停止中か・つながるか）
  └ BRIDGE へ {type:"testEvent"} を送り、返事を待つ（15秒まで）
BRIDGE（bridge/index.js）
  ├ 設定ファイルを読み直す（イベント設定・割り当て）
  ├ 入力を TikTok のイベントと同じ形にする（bridge/test_fire.cjs）
  ├ 本番と同じ処理の関数に、テスト用の新しい状態を渡して通す
  ├ 本番と同じ送る列（再送・分割・requestId）で BridgeMOD へ送る
  └ BridgeMOD が受け付けるまで待つ（10秒まで）→ 結果を main へ返す
```

## 3. main と BRIDGE の受け渡し

BRIDGE は今も ipc の通り道つきで起動している（今は停止の `{type:"shutdown"}` だけを送っている）。同じ通り道に、問い合わせと返事を1組足す。

main から BRIDGE へ:

```js
{ type: "testEvent", id: "<uuid>", input: {
    type, preview, listenerName, commandFile, giftId, count,
    previousLikes, likeCount, deaths, followCount, comment, pollOption } }
```

BRIDGE から main へ:

```js
{ type: "testEventResult", id: "<同じ uuid>", result: {
    ok: true, preview: false, sender: "整えた表示名",
    steps: [{ label, commandFile, count, type }],   // 送る列に入れた（入れる）もの。列の1件が1件。ルーレットは1件
    notes: ["…"],
    fired: [{ stepIndex, commandFile, count, state, message }] } }  // 送ったときだけ
// 入力の誤り・使えないとき
{ type: "testEventResult", id, result: { ok: false, error: "テストするコメントを入力してください。" } }
```

- `state` は次の4つ。
  - `delivered`: BridgeMOD が受け付けた
  - `pending`: 10秒たっても送り直し中、またはルーレットを回している途中
  - `failed`: BridgeMOD が受け付けなかった（400 など。再送しない）
  - `discarded`: 配信の終了でいいねを捨てたときに一緒に捨てた
- main は `id` で返事を待つ。15秒たっても返事がなければ「BRIDGE から返事がありません。BRIDGE のログを確認してください。」を出す。待っている間に BRIDGE が終了したら「BRIDGE が止まったため、結果を受け取れませんでした。」を出す。
- `ok: false` の返事は、今の入力の誤りと同じく例外にして画面に出す。
- 画面に出す文（「N件中M件を…」「条件に一致しました（未送信）」）と一時停止中の一文は、今と同じく main が作る。
- BRIDGE を単体で起動したとき（ipc の通り道がない）は、この問い合わせを受けない。

## 4. BRIDGE の中の作り

### 4.1 本番の処理を関数に分ける

bridge/index.js のギフト・いいね・シェア・フォロー・訪問・コメント・死亡（デスルーレット）の処理のうち、BridgeMOD へ送る部分を「状態と送り先を引数で受け取る関数」にする。本番は今の状態を渡して呼び、テストは新しい状態を渡して呼ぶ。処理の中身（判定・回数・アナウンス・順番）は1か所だけに書く。

引数で受け取るもの（以下「文脈」と呼ぶ）:

| 文脈の中身 | 本番 | テスト | 条件だけ確認 |
|---|---|---|---|
| FeatureEngine（コンボ・マイルストーン・コメントコマンド・投票） | 今のもの | 毎回新しく作る（設定は本番と同じ options.gameplay） | 同左 |
| クールダウン・連打・コメントギフトの3秒の記録 | 今のもの | 毎回空 | 毎回空 |
| 二重受信の除去 | 使う | 使わない | 使わない |
| いいねのまとめ送り | 今のもの | 毎回新しく作る（待ち時間は本番と同じ） | 使わず、そのまま記録 |
| 送り先 | 送る列（modDelivery） | 同じ送る列。イベントにテストの印を付ける | 記録するだけ |
| ルーレット | 本番の順番待ちの列 | 同じ列。当たりにテストの印を付ける | 「ルーレット（N回）」と記録するだけ |
| 音・粒子（コメントギフト） | 送る | 送る | 送らない |
| 読み上げ | する | しない（読み上げは読み上げ設定のテストで確かめる） | しない |
| ログ | 今のまま | 行頭に `[Test]` を付ける | 同左 |

- RCON・7DTD へ送る部分は今のまま残す。テスト発火は BridgeMOD 経路のときだけ使える。それ以外の設定では「テスト発火は、Minecraft を BridgeMOD で動かしているときだけ使えます。」を返す。
- 本番の入口で先に行う確かめ（配信終了後のいいね・接続前のイベント・いいねの累計の計算）は本番の入口に残す。ミュートの照合は本番と同じ関数をテストの入口でも使う。
- ルーレットへの差し替え（コマンド名が roulette のとき）は、送り先の手前の1か所で行い、3つの文脈で同じものを通す。

### 4.2 テストの印と結果の集計

- テストで送るイベントには、印として `source: "test"` とそのテストの集計先を持たせる。BridgeMOD へ送る本文は今の決まった項目だけで作るので、印は BridgeMOD に届かない。
- 送る列の「送れた」「送れなかった」の記録で、印のあるものは履歴に `source: "test"` を付けて書き、集計先へも知らせる。
- 印のあるイベントの「送れなかった」は、ホーム画面の「Modへ送れなかったイベントがN件」には数えない（テストの結果に出す）。
- 集計先は、送る列に入れたもの・ルーレットの回数・まとめ送りの待ちの数を数え、全部が終わるか10秒たったら結果を返す。10秒の時点で終わっていないものは `pending` にする。返したあとに届いたものも、履歴には届いたときに書く。
- テストのイベントも本番と同じ列に並ぶ。配信中なら、先に来たギフトのあとに送る。

### 4.3 設定

- テストを始める前に、設定ファイルを読み直す（今の自動の読み直しと同じ確かめを通す）。保存した直後でも、新しいイベント設定・割り当てで試せる。
- options（ミュート・アナウンス・コンボ・マイルストーン・投票・クールダウンなど）は、本番と同じく BRIDGE の起動時の値を使う。保存してある options が起動時と違うときは、次の注意を notes に入れる。
  「設定のうち、ミュート・アナウンス・コンボ・マイルストーン・投票などは、BRIDGE を起動し直すまで本番にもテストにも反映されません。いまの BRIDGE の設定で試しました。」

## 5. テストの種類ごとの入れ方

入力の確かめと変換は bridge/test_fire.cjs にまとめる（ファイルを読まない純粋な関数にして、単体で試せるようにする）。

| 画面の種類 | 通す処理 | 入れるもの |
|---|---|---|
| ギフト（コマンド直接） | 送り先（ルーレットへの差し替えを含む） | type gift、選んだコマンド、count N（1〜100）の1件、アナウンスは本番の設定。割り当て・倍率・コンボは通さない |
| 設定済みギフト・コンボ | ギフトの処理 | ギフトID。同じ視聴者の連打として repeatCount を 1 から N まで1つずつ入れ、最後に repeatEnd を付ける（N は1〜100） |
| 未設定ギフト | ギフトの処理 | 割り当てのないギフトID を1個（repeatCount 1、repeatEnd） |
| いいね・いいねマイルストーン | いいねの処理（累計の計算のあと） | 前回の累計＝入力の前回、今回の累計＝入力の今回（0〜1000000、今回は前回以上） |
| シェア・訪問 | それぞれの処理 | 送り主だけ |
| フォロー・フォローマイルストーン | フォローの処理 | 新しい FeatureEngine のフォロー数を「入力の人数−1」にしてから1回通す |
| コメント・コメントコマンド | コメントの処理 | コメント（空は不可、500文字まで） |
| 死亡 | デスルーレットの処理 | 累計死亡回数、プレイヤー名＝送り主 |
| ルーレット | ルーレットの列 | 今のルーレット設定で1回 |
| コメント投票の当選 | FeatureEngine の投票 | 投票を始め、`!番号` のコメントを1つ入れ、すぐ締め切る |

- 送り主は `nickname` として入れ、本番と同じく整えた表示名にする。空なら「テスト視聴者」。
- 設定済みギフトで割り当てのない ID、未設定ギフトで割り当てのある ID は、今と同じく notes に理由を書いて何も送らない。
- ミュート対象の送り主は「この視聴者はミュート対象のため発火しません。」とだけ返す（死亡は本番と同じくミュートを見ない）。
- コンボ・マイルストーン・コメントコマンドは、本番と同じく元のギフト・いいね・フォロー・コメントの設定も一緒に動く。画面の選択肢はそのまま残し、そのことを画面に書く。
- 投票は FeatureEngine に「すぐ締め切る」関数（finishPoll）を足す。本番の締め切りの時間切れも同じ関数を呼ぶ。テストで始めた投票は時間切れを待たない。
- 今あった「一度に100件まで」の上限はなくす（本番にない上限のため）。

## 6. 条件だけ確認（送らない）

- 送るときと同じ関数を、記録するだけの文脈で通す。手順の一覧と notes を返す。
- 送る前の確かめ（コマンド名・GAME_MOD の書き方・コマンドファイルがあるか）は送るときと同じものを通し、通らないものはその手順の理由として notes に出す。
- RANDOM の抽選は送るときと同じく行い、「ランダム選択: 〇〇.txt（実行ごとに抽選）」を notes に出す。
- BridgeMOD がつながっていなくても使える。BRIDGE が止まっているときは使えない。

## 7. BRIDGE・BridgeMOD が動いていないとき

- BRIDGE が止まっている: テスト発火も条件だけ確認も使えない。画面はボタンを押せなくし、「BRIDGE を起動すると試せます。」を出す。main も同じ文を返す（画面の表示が遅れて押せたとき用）。
- 送るときに BridgeMOD の状態が読めない（つながらない・時間切れ）: 送る列に入れずに「Minecraft サーバー（BridgeMOD）につながりません。サーバーを起動してから試してください。」を返す。止まっている間に入れると、あとでサーバーを起動したときに思いがけず動くため。HTTP の応答が返ったとき（403 など）はつながっているので送る。
- BridgeMOD が応答はするが混んでいる（429・5xx など）: 本番と同じく送り直す。10秒で届かなければ「送り直し中（届いたら実行されます）」と出す。
- 一時停止中: 今と同じく受け付け、「一時停止中です。再開すると実行されます。」を足す。

## 8. 画面（EventTestPanel）

- OperationsPage が持っている BRIDGE の状態（bridgeProcess.running）を受け取り、止まっているときは2つのボタンを押せなくして理由を出す。
- 結果の行に `state` ごとの文を出す。
  - delivered: 「BridgeMOD が受け付けました」
  - pending: 「送り直し中（届いたら実行されます）」。ルーレットは「ルーレットを回しています（当たりは回したあとに送ります）」
  - failed: BridgeMOD の理由
  - discarded: 「配信の終了で取りやめました」
- 同じ内容（見出し・コマンド・回数・状態）の手順が続くときは「×N回」とまとめて1行にする（ギフト100個で100行にしない）。
- コンボ・マイルストーン・コメントコマンドを選んだときに、元のイベントの設定も動くことを1行で書く。
- 未保存の変更があるときに押せないのは今のまま。

## 9. 消すもの

- electron/event_tests.cjs（planTestEvent）
- electron/main.cjs の fireBridgeEventMaybeRoulette と、テスト発火のために main が履歴を書いていた部分。テスト発火のためだけに読み込んでいるもの（ルーレットの関数など）も外す
- planTestEvent を直接試しているテスト（event-tests・bridge-count-limit・bridge-minor-fixes・command-files の該当部分）は、BRIDGE 側のテストへ移す。RCON 向けの回数の上限のテストは、テスト発火が BridgeMOD 経路だけになるので消す

## 10. テスト

1. bridge/test_fire.cjs の単体テスト: 種類ごとの変換、入力の範囲、ミュート、割り当てのない ID。
2. 本番と同じかのテスト（bridge-fixture）: 同じ内容を、仮想の TikTok から送ったときとテストの問い合わせで送ったときで、偽 BridgeMOD に届いた要求（type・key・count・announce・順番）が同じになることを確かめる。requestId・eventId は比べない。
   - いいね: 閾値10で 0→100（追いつき上限5を超える）。100未満の閾値はアナウンスなし
   - いいね: マイルストーンとルールの順番
   - フォロー: フォローマイルストーンとフォローの順番
   - コメント: コメントコマンドとコメントギフトの順番
   - 訪問: アナウンスなし
   - 設定済みギフト N 個: 連打と同じ回数・同じ回数の要求、時限倍率の四捨五入
   - ルーレット: 当たりが type other・アナウンスなし
   - 送り直し: 偽 BridgeMOD が初めに 503 を返しても、届いたら delivered になる。10秒を過ぎたら pending
   - 400 は failed になり、ホーム画面の送れなかった件数に数えない
   - 履歴に `source: "test"` が付き、本番の行と同じ種類名になる
3. FeatureEngine の finishPoll: すぐ締め切ると、時間切れのときと同じ当選を出し、あとから時間切れでもう一度出さない。
4. main（app-regressions）: BRIDGE が止まっている、返事の受け渡し、15秒の時間切れ、待っている間の BRIDGE の終了、BridgeMOD につながらないときに送らない、一時停止中の一文。
5. 画面（ソースのテスト）: BRIDGE が止まっているときにボタンを押せない、state ごとの文、同じ手順のまとめ。

## 11. 使う人から見て変わること

- いいねのテストで、追いつき上限による省略がなくなる（本番と同じ）。
- ギフト N 個のテストは、N 回に分けて送る（本番の連打と同じ）。アナウンスも回ごとに出る。
- 訪問と100未満のいいねでは、テストでもアナウンスが出ない（本番と同じ）。
- マイルストーン・コンボ・コメントコマンドのテストで、元のイベントの設定も動く。
- BRIDGE を起動していないと、テスト発火も条件だけ確認も使えない。
- サーバーが止まっていると送れない。混んでいるときは送り直し、届いたら実行される。
- ミュート・アナウンス・ゲームプレイの設定を変えたら、BRIDGE を起動し直すまでテストにも反映されない（本番と同じ。画面に注意を出す）。

## 12. 範囲外

- RCON・7DTD でのテスト発火
- 読み上げのテスト（読み上げ設定の画面に別にある）
- 一時停止中に預けたイベントを、サーバーの停止・再起動のあとまで残すこと（HANDOFF04 に未決として記録済み）
