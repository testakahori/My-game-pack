# UI・UXレビューと実装記録 — 2026-10-17

対象は MyGamePack v1.0.46 の配信準備・設定・管理画面。初めて設定する配信者と、毎回起動する配信者を想定して確認した。レビューで挙げた以下の改善はすべて実装した。

## 結論

一番の問題は、主操作の埋もれ、保存方法の曖昧さ、実際には確認していない状態を完了に見せる表示だった。既存のダークカラーを残し、シアンを主操作に使う。待機中の赤や強い発光を抑え、文字・余白・操作サイズを整えた。

- 配信ホームの「一括起動」を状態図より上へ移動。ゲームの詳細説明は開閉式にした。
- 待機・処理中・稼働・エラーを状態に応じて表示。MAP保存とLIVE STUDIOの接続は自分で確認する項目と明記した。
- 設定保存を下端の共通バーにまとめ、未保存・保存中・保存成功・失敗を表示。再編集後は古い成功通知を隠す。
- ギフト割り当ての保存と、JSONファイルへの書き出しを区別。未選択時の架空の価格・コマンドを除去した。
- データ未取得と検索結果0件を区別し、取得・再読込・絞り込み解除へ進めるようにした。
- スイッチや入力に名前を付け、フォーカスを見やすくした。スキップリンクも追加した。
- TOP／ダッシュボードという呼び方を配信ホームへ統一し、ゲーム設定へ戻るボタンを設けた。
- 1120px幅では設定行を折り返し、ホームの手順を下へ移動。発光を抑えて配信状態と主操作が目立つようにした。

## 確認した順序と判定

判定は「良好」「要改善」「重大」。重大は操作判断を誤らせる問題、要改善は迷いや視認性の問題。改善後の判定は今回確認できた開発用ブラウザー上の範囲に限る。

| 順序 | 操作・画面 | 改善前 → 改善後 | 観察と実装 |
| --- | --- | --- | --- |
| 1 | ゲームを選択・保存 | 要改善 → 良好 | 長い説明が初回操作を埋める。詳細を開閉式にし、未保存と適用済みを常時表示。 |
| 2 | 配信ホームで起動を準備 | 重大 → 良好 | 起動ボタンが下にあり、固定手順が完了を誤認させる。主操作を前へ、実測と手動確認を区別。 |
| 3 | ギフトを割り当てる | 要改善 → 良好 | ファイル保存と割り当て保存が混同しやすい。操作名を分離し、未選択プレビューを正確にした。 |
| 4 | いいね・フォローを設定 | 要改善 → 良好 | 小さな操作と不明瞭な保存状態。共通保存バー、読み上げ名、折り返す設定行を追加。 |
| 5 | ルーレット・コメントを設定 | 要改善 → 良好 | 長い画面で保存先が遠い。保存バーと項目ごとの操作名を追加。 |
| 6 | 読み上げを設定 | 要改善 → 良好 | 保存状態を追いにくい。保存バーを追加し、音声テストの結果と保存通知を分離。 |
| 7 | 配信画像を作る | 要改善 → 良好 | ギフト未取得でも検索条件の変更を案内する。未取得を明示しギフト一覧への導線を追加。 |
| 8 | ギフト一覧を調べる | 要改善 → 良好 | 未取得の最安・最高額が0。未取得は「—」、検索0件から解除できるようにした。 |
| 9 | コマンドを検索 | 要改善 → 良好 | 読込中と0件を区別できず復帰手段もない。状態分岐、再読込、絞り込み解除を追加。 |
| 10 | 運用センターを確認 | 良好 → 良好 | 既存の管理区分を維持。共通の文字・フォーカス改善と配信ホームの名称統一を適用。 |
| 11 | 配信統計を確認 | 良好 → 良好 | 既存の集計・空状態を維持。共通の視認性とフォーカス改善を適用。 |
| 12 | 初期セットアップ完了を確認 | 重大 → 良好 | 静的画像がTikTokまで準備済みに見せる。サーバー構築完了だけを明記し、未計測の擬似メタ情報を除去。 |

## 検証と範囲

- `npm run verify`：型チェック、Bridgeシミュレーション、アプリテスト383件、本番ビルド。
- スイッチの読み上げ名、保存失敗からの再試行、未確認項目の手動確認表示、起動状態の区別、再編集時の通知について5件の回帰テストを追加。
- 修正前の `origin/main` を `git archive` で一時コピーに取り出し、スイッチの読み上げ名のテストが失敗することを確認。新しい保存バーと手順コンポーネントは修正前に存在しない。
- ブラウザーで11画面の遷移と1120px／1488px幅の横はみ出しを確認。新しい検証タブで実行エラーなし。
- Spaceキーでスイッチ切替 → 未保存 → 保存成功 → 再編集で古い保存成功を表示しないことを確認。
- コマンド検索0件 → 解除 → 55件の一覧が復帰することを確認（割り当て用の56件からルーレット専用項目を除外した件数）。
- 開発APIを使ったブラウザー確認。実アカウントへの接続、配信開始、Minecraft／BRIDGEの実プロセス起動、OSのファイル選択、音声再生はこのUIレビューでは実行していない。
- 未保存で画面移動すると確認待ちに入ったが、ブラウザー操作APIからそのダイアログを取得できず、キャンセル操作の再検証は未完。既存の未保存ガードは変更していない。保存操作と保存後の画面遷移は別タブで確認した。

## コードレビュー

差分を通読し、保存処理や起動処理の呼び出し先、スイッチの全利用箇所、メッセージのnull参照、既存の未保存ガード、最小幅のCSSを確認した。確認中に見つかったメッセージ参照ミスと狭幅のグリッド配置を修正し、全画面を再確認した。新しい依存パッケージは追加していない。
