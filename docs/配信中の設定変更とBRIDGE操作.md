# 配信中の設定変更とBRIDGE操作

いいねのしきい値・コマンド・回数、ギフトの割り当ては、保存後に稼働中のBRIDGEが数秒で自動反映します。BRIDGEの再起動は不要です。保存前の編集内容は反映されません。

配信ホームの「BRIDGEだけを操作」には次のボタンがあります。

- **BRIDGE起動**：TikTokとの連携だけを起動します。
- **BRIDGE停止**：連携を停止します。Minecraftとサーバーはそのまま動きます。
- **BRIDGE再起動**：連携を停止してから再接続します。接続アカウントを変更したときにも使います。

これらの単体操作で、天候やゲームルールを再設定することはありません。すべてを止める場合は「一括停止」を使ってください。

「100いいね・タラ・1回」は、受信した累計が100の倍数を越えるごとに1回実行します。最初のパケットに含まれる新しいいいねも数えますが、接続前に蓄積されたいいねをまとめて実行はしません。再接続中に受信できなかった分は対象外です。

v1.0.41ではTikTokコネクターの現行データ形式（いいねのcount/total、贈り主のuser.nickname、イベントのcommon）に対応しました。名前が空の場合はアカウントID、ユーザーIDの順に使い、どれも届かない場合のみunknownになります。

いいねが動かない場合は、ルールが有効で保存済みか、BRIDGEがTikTokへ接続済みか、Minecraftのプレイヤーがサーバー内にいるかを確認してください。接続ログには条件に達したときの累計と実行コマンドが表示されます。


## v1.0.42 起動済みサーバーとライブ状態・コメント読み上げ

TikTok欄は入力したアカウントの配信状態を30秒ごとに確認し、配信中なら「接続済み（配信中）」、配信していなければ「配信していません」と表示します。通信失敗は「確認できません」として区別します。BRIDGE停止中でも確認しますが、ギフト・いいね・コメントの受信にはBRIDGEの起動が必要です。

アプリを開き直す前からMinecraftサーバーが動いている場合は、Forge欄に「起動済み（アプリ外）」と表示します。一括起動はそのサーバーを使用し、ワールド保存や二重起動を行いません。アプリ外のサーバーを停止する場合は、起動した画面で stop を実行してください。MAP操作も停止後に行います。

起動・停止の進行とエラーはボタンの直下に表示します。ログが増えてもページ全体を勝手にスクロールしません。通常の停止でもワールド保存を最大2分待ち、完了しなければ強制終了せず未完了として知らせます。

現行TikTok形式のコメント本文contentにも対応しました。「読み上げ」と「コメント読み上げ」を有効にすると、名前と本文を読み上げます。コメント連動コマンドにも同じ本文を使います。
