# 配布者から受け取るアプリ更新

2026年10月3日、アプリ1.0.46から手動配布へ変更しました。GitHubリポジトリは非公開です。2026年10月24日から、インストーラーは公式 HP から配ります。

## 配布者の手順

1. `npm run release:win` でインストーラーを作ります（下の「ビルドとリリース」）。
2. できた `release/MyGamePack-Bridge-UI-Setup-バージョン.exe` を公式 HP にアップロードします。
3. 購入者は、配布者が発行した番号で公式 HP にログインし、そこからインストーラーをダウンロードします。GitHubの閲覧権限を利用者へ渡す必要はありません。

最新版はインストーラー全体を配布してください。利用者が設定ファイルやMODを個別に差し替える必要はありません。

## 利用者の手順

1. 設定を保存し、BRIDGE・サーバー・Minecraftを停止します。
2. アプリを終了し、配布者から受け取ったインストーラーを実行します。
3. 現在と同じインストール先を選びます。
4. 更新後にアプリを起動し、運用センターの「アプリのバージョン・更新方法」で版を確認します。

更新後に初期セットアップ（「既存セットアップを使う」など）を終えたとき、今選んでいるゲームの MOD（BridgeMOD・DisplayMOD・採掘MOD など）の jar を、サーバーと Minecraft の両方で新しい版に入れ替え、ゲームのコマンドも新しくします。ほかの MOD やファイルには触りません。入れ替えた古い jar は、各フォルダーの `.mygamepack-mod-switch/<処理ID>/replaced` に残ります。サーバーや Minecraft が動いていて入れ替えられなかったときは、何も変えずに、次に起動したときにもう一度試します。ホームに「アプリの更新でMODが古いままです」と理由が出たら、サーバーと Minecraft を止めてから「今すぐ入れ替える」を押してください（ほかの MOD はそのまま残ります）。まだ一度もゲームを「保存」していないときは何もしません。

事前のアンインストールは不要です。既存の設定・ゲーム別プロフィール・MAPを引き継ぎます。

## 変更点

アプリ起動時の更新確認、インストーラーの自動ダウンロード、再起動による適用を廃止しました。アプリから非公開GitHubへ接続して更新する処理はありません。GitHubの認証情報もアプリには含めません。

運用センターには現在のバージョンと更新手順を表示します。「更新を確認」「再起動して適用」のボタンはありません。旧画面から更新用IPCが呼ばれた場合も、手動更新の案内だけを返します。

ギフト一覧の更新や、インストール後のBRIDGE資材の同期は従来どおりです。これらはアプリ本体の自動更新とは別の処理です。

1.0.45以前のアプリには自動更新処理が残っています。非公開リポジトリからは自動更新できないため、初回もこの手順で1.0.46以降を配布してください。

## ビルドとリリース

埋め立て PR3（専用マップの切り替えと「マップを初期化」）がマージされるまでは、`npm run release:win` で配布用のインストーラーを作りません（2026-10-29 ユーザーの決定）。PR2 の時点では、ゲームで「埋め立て」を選ぶと UmetateMOD だけが入り、専用マップは入らないためです。試し用の版（下の `scripts/package-local.cjs`）は作ってかまいません。

MOD を変えたときは、先に BridgeMOD・DisplayMOD・採掘MOD・埋め立てMOD の jar を作り直しておきます（作り方は `AGENTS.md`。MOD を変えていなければ不要）。そのうえで、リポジトリの直下で `npm run release:win` を1回動かします。次の順に必ず通ります。

1. 版を確かめる（`package.json` の version が 1.2.3 の形）。
2. MOD の作り直し忘れを確かめる。jar が無い、または jar の元と今のソースが違うときは、何も作らずに止まる。
   - MOD を作ると、jar の横に `<jar>.inputs.json`（元の中身のハッシュ）が書かれる。あれば中身で比べるので、git でブランチを切り替えて時刻だけ新しくなっても止まらない。ソースを変えた・消した・足した、jar を作っている間に保存した、のどれでも止まる。
   - `.inputs.json` の無い古い jar は、ソースが jar より新しいかで比べる。
   - 採掘MOD と埋め立てMOD は BridgeMOD を使って作るので、BridgeMOD を直したら採掘MOD・埋め立てMOD も作り直す。
3. 作った物の置き場（`build/server-template`・`build/game-packs`・`GiftsViewer/tools-bundled`）を空にする。エクスプローラーなどで開いていて消せないときは、閉じるよう案内して止まる。
4. 画面のビルドと、BRIDGE・サーバーの雛形・ゲームパックの準備（MOD の jar は、作っておいたものを同梱する）。
5. `scripts/package-windows.cjs` でインストーラーを作る（`build.publish` は null で、自動更新フィードは作らない）。
6. 最後に、できたインストーラーの場所、どのコミットから作ったか（コミットしていない変更の数も）、同梱した MOD の jar を表示する。今回のインストーラーができていなければ、成功と表示せずに止まる。

electron-builder が「Incomplete production dependencies」で止まったときは、`node_modules` に前の版で使っていたパッケージ（`electron-updater` など）が残っています。`npm ci --ignore-scripts` で `package-lock.json` どおりに作り直してから、もう一度動かします（CI・`docs/ローカル更新.md` と同じ）。`node_modules` がジャンクションやリンクのときは、先にそれを外してから動かします（つないだ先まで消さないため）。

インストーラーは `release/` にできます。公式 HP へのアップロードは、配布者が手で行います。`scripts/package-windows.cjs` を直接動かすと止まります（ビルドと準備を通らず、前に作ったものが入るため）。`latest.yml` と差分更新用の blockmap は、配布には不要です。

試し用の版（version に `-local.` を含む）は `npm exec -- node scripts/package-local.cjs <出力先>` で作ります。同じ流れを通ります（`docs/ローカル更新.md`）。
