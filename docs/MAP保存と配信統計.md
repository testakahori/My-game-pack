# MAPセーブ・ロードと配信の自動記録

## MAPを保存・復元する

配信ホームの「MAPの保存・読込を開く」、または「運用センター」→「MAPセーブ・ロード」を開きます。

- 遊ぶ前にセーブ名を入力し「保存する」を押します。空欄なら日時を名前にします。
- 戻したいMAPの「このMAPをロード」を押し、確認すると、地形・各ディメンション・持ち物・プレイヤーの位置を含めて復元します。
- 保存一覧に追加するのは「保存する」を押した時だけです。サーバー起動時・ロード前の自動保存は行いません。ロードで現在の変更は置き換わるので、残したい場合は先に保存してください。
- サーバーがこのアプリから起動している場合は、Bridgeを止め、Minecraftへ保存・停止を要求します。正常終了を確認してから操作し、成功後に元の起動状態へ戻します。Minecraftには再接続してください。
- 停止が終わらない場合は強制終了してコピーせず、MAP操作を中止します。別アプリから起動したサーバーも、停止を確認できなければ操作しません。
- ファイルのハッシュを照合してから復元します。復元の入れ替え途中で中断した場合は、次回の保存・読込・サーバー起動前に復旧を試みます。エラーが出たら保存先を変更せず、元のフォルダーを保持してください。

保存先は、選択中のサーバーフォルダー内の map-saves です。過去の名前付き・自動退避・起動前のセーブは保持します。ロード中は失敗時の復旧用に一時フォルダーを使い、成功・復旧後に削除します。保存一覧には追加しません。古いZIPバックアップは保持しますが、この一覧からのZIP読込には対応していません。ギフト・読み上げ等の設定はMAPには含みません。

従来の保護エリアUIは廃止し、Bridgeから送信するコマンドのエリア保護も無効です。以前の座標設定は互換性のため設定ファイルに残ります。

## 配信は接続中に自動記録

TikTok LIVE STUDIOでライブを開始し、アプリのダッシュボードからTikTokへ接続すると、自動で配信記録を作ります。終了イベントを検知すると終了を記録します。開始・終了の手動ボタンは不要です。

TikTokの配信IDごとに1つの記録を作ります。同じ配信へ再接続した場合は同じ記録に接続区間を追加し、別の配信IDなら短い間隔でも別の記録にします。イベントがゼロでも記録を残します。

記録時間は接続中に観測できた区間の合計です。接続前・切断中・アプリ停止後の時間をTikTokからさかのぼって取得する機能ではありません。通常のアプリ・Bridge停止時は記録を閉じ、異常終了時は最終確認時刻で打ち切ります（確認は約15秒間隔）。未接続での配信開始・終了は検知できません。

過去の手動記録は保持し、記録のない過去のイベント履歴は90分以上の間隔で分けた推定として残します。

## 配信ごとの履歴と比較（v1.0.43）

「配信統計」を開くと、過去の配信一覧を最初から表示します。「見る」で選んだ配信の詳細へ移動できます。「7日・30日で比較」では、直近の期間とその前の同日数を比較します。開始日時で期間に振り分け、記録中の配信も含めます。

- 受信ギフト個数、TikTokコイン相当、いいね数、コメント、フォロー・シェア・訪問通知を、コマンドの割り当て・有効設定・実行成功とは独立して記録します。
- コイン相当はギフト単価×受信個数です。薔薇1個・1コインをコマンド100回に設定しても、ギフトは1個・1コインです。連打ギフトは増分を数え、終了通知で二重加算しません。
- コイン相当は実際の受取額ではありません。詳細の「実際の受取額（任意）」へTikTokで確認した円の金額を入力すると、期間ごとの入力済み金額を比較できます。固定レートでの換算は行いません。空欄で保存すると未入力へ戻ります。
- 単価が取れなかったギフトは個数を別記します。コイン相当は既知分の小計です。フォロー等は通知回数で、純増人数やユニーク人数ではありません。
- 比較には、受信数を取得できた配信数と受取額の入力済み配信数も表示します。接続時間あたりのコイン相当で配信時間の違いも確認できます。
- 旧バージョンの配信は履歴を残し、未記録の受信数を「未取得」と表示します。コマンド履歴からギフト数や売上を推測で復元しません。

配信記録は stream-sessions.json、受信統計は stream-audience.json、手入力の受取額は stream-earnings.json に保存します（選択中サーバーの bridge 内）。これらは30日を超えて保持し、アプリ更新でも保持します。コマンドの動作履歴だけは従来の保持上限の対象です。保存は約1秒間隔と正常停止時です。突然のプロセス終了では最後の未保存分が欠ける可能性があります。MAPの保存とは無関係です。

## Markdownで分析用に保存

「全履歴をMDで保存」で保存済みの配信をまとめて書き出します。詳細の「この配信をMDで保存」は選択した1配信だけを書き出します。ファイルはローカル保存で、GPTへの自動送信は行いません。

MDには配信ID、開始・終了/最終観測、接続区間、受信ギフトの種類・単価・個数・コイン相当、いいね等の受信数、手入力の受取額、視聴者数、全履歴の場合は7日・30日の比較を記載します。時刻はUTCです。コマンド要求回数は診断用に分けて記載し、売上と混同しません。未取得・途中接続・切断中の欠損・テスト除外など、分析に必要な条件も先頭に記載します。
